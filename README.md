# ماسال — لوحة إدارة البطاقات الإلكترونية

المرجع: «تحليل مشروع ماسال.pdf»، 24 صفحة، النسخة الأولى. تمت مراجعة الملف كاملًا، بما في ذلك المعادلات غير المكتملة في الاستخراج النصي.

## نطاق التسليم
واجهة إدارة عربية تفاعلية لجميع الوحدات المقترحة، مع بيانات توضيحية محفوظة على الخادم. هذه بيئة مراجعة للواجهات وليست نظام دفع أو إصدار PIN إنتاجيًا. تظهر وظائف التكامل والأجهزة التي تتطلب مواصفات خارجية كوظائف بانتظار الربط، دون ادعاء تنفيذها.

## المصطلحات والقواعد
- System Owner: مدير النظام الرئيسي. Supervisor: المشرف ونطاق الوكلاء المكلف بهم.
- Main Agent: وكيل رئيسي يملك مخزنًا مستقلًا. Sub-Agent: وكيل فرعي يملك محفظة ويسحب من مخزن الرئيسي.
- POS: نقطة بيع تتبع وكيلًا واحدًا، مرتبطة بجهاز وموقع جغرافي.
- Provider: المزود؛ Operator/Brand: شركة الاتصالات أو العلامة؛ Supplier: الجهة المجهزة. دور الاتحاد لم يحسم.
- Batch: دفعة البطاقات التابعة للطلبية. لا تحذف طلبية استُخدمت منها بطاقة.
- Provider Serial مختلف عن Internal Serial. لا تحفظ هذه النسخة أي PIN أو CVC أو Token حقيقي.
- فصل سجل مخزون البطاقات، سجل تكلفة المخزون، سجل المحافظ، وسجل المبيعات والأرباح.
- FEFO: الأقرب انتهاءً أولًا؛ FIFO: الأقدم إدخالًا عند تساوي الانتهاء.
- الفئة التي لا تملك سعرًا فعالًا أكبر من صفر غير متاحة للبيع.
- فشل الطباعة بعد كشف PIN لا يعيد البطاقة للمخزون ولا يصدر بطاقة أخرى تلقائيًا.
- Quarantined وExported يخرجان البطاقات من المتاح؛ التسوية المالية تنتظر نتيجة المطالبة.
- إجمالي المبيعات = الكمية × سعر البيع؛ تكلفة البضاعة المباعة = الكمية × تكلفة الشراء؛ الربح الإجمالي = الفرق.

## تغطية وحدات المخطط
1. الهوية والمستخدمون — الحسابات والأدوار وحالة المصادقة.
2. الصلاحيات ونطاق الشجرة — مصفوفة الأدوار ومجموعات الوكلاء.
3. الشركات والمزودون — الفصل بين العلامة والجهة المجهزة ونوع الربط.
4. المنتجات والفئات — المحلي والعالمي والقيمة الاسمية والحقول.
5. الطلبيات والاستيراد — مسودة ومراجعة وفحص عينة CSV لا تتضمن أسرارًا.
6. مخزون PIN والدفعات — عرض معلومات الدفعات دون رموز حقيقية.
7. المحافظ والحسابات — أرصدة نموذجية منفصلة عن المخزون.
8. الأسعار — السعر الفعال والحد الأدنى وتاريخ السريان.
9. الوكلاء — الرئيسي والفرعي والشجرة.
10. نقاط البيع والأجهزة — الجهاز والرقم التسلسلي والموقع وآخر اتصال.
11. البيع والطباعة — حالات الإصدار والطباعة وبيانات العملية.
12. إعادة الطباعة والاستثناءات — سبب ومحاولات وحالة كشف PIN.
13. البطاقات التالفة والمطالبات — عزل ونتيجة المطالبة.
14. التصدير الآمن — مراجعة الطلبات؛ تصدير أسرار فعلي ينتظر البنية الإنتاجية.
15. تكاملات API — بيئات الاختبار والإنتاج وبيانات اعتماد الوكيل دون أسرار فعلية.
16. الإشعارات والتنبيهات — مسودات إشعارات وتنبيهات تشغيلية.
17. الدعم الفني — تذاكر وردود وتصعيد وإغلاق في بيئة المراجعة.
18. الخرائط والانتشار — مواقع توضيحية ونطاق الوكيل والإحداثيات.
19. التقارير — مبيعات وتكاليف وربح مع تصدير CSV آمن.
20. سجل التدقيق — عمليات التعديل قبل وبعد، دون واجهة حذف أو تعديل.
21. المراقبة والأمان — مؤشرات نموذجية وسياسات إيقاف مقترحة، دون اتصال تشغيلي حقيقي.
22. الهوية البصرية — إعدادات الوكيل وقالب وصل توضيحي.
23. إدارة صفحة الهبوط — مسودات أخبار وسلايدرات وروابط التطبيقات.
24. النسخ الاحتياطي والاستعادة — تصدير بيانات المراجعة؛ استعادة إنتاجية غير متصلة.

## المطلوب قبل التشغيل الحقيقي
توثيق القواعد المالية والسقوف والرسوم، عينات ملفات المزودين، مواصفات أجهزة POS وبروتوكولات تأكيد الطباعة، وثائق API وWebhooks وبيئات الاختبار، إدارة مفاتيح التشفير، تنفيذ المصادقة متعددة الأدوار ونطاق الشجرة على الخادم، مراجعة أمنية ومحاسبية واختبار التزامن والانقطاع والتكرار، واعتماد ترجمة كردية وإنجليزية للواجهات.
## التحقق
نجح بناء النشر وفحص TypeScript، واختبارات API لحفظ سجل ثم تعديله وإعادة قراءته، وتسجيل القيم السابقة والجديدة، ورفض تعارض الإصدار، والسعر صفر أو الأقل من الحد التعاقدي، وتعديل طلبية تجاوزت المسودة، وتغيير المحافظ للقراءة فقط.

لم تُطلب اختبارات متصفح. أضيفت أداة WebMCP للتنقل بين الوحدات مع فحص المدخلات، لكن لم يتوفر سياق تحقق WebMCP؛ لا ندعي اختبارها.
